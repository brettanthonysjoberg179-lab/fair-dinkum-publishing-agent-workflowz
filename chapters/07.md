## The BaseAgent contract

Every agent in the workforce inherits from a single `BaseAgent` class. This isn't premature abstraction — it's the contract that lets the workflow service treat all agents identically while each one does radically different work.

```python
class BaseAgent:
    name: str
    version: str = "1.0.0"
    
    async def execute(self, context: AgentContext) -> AgentResult:
        ...
    
    def validate_input(self, context: AgentContext) -> bool:
        ...
    
    def rollback(self, context: AgentContext) -> None:
        ...
```

The `AgentContext` carries the project ID, current phase, accumulated artifacts from previous agents, and a reference to the database session. The `AgentResult` returns status, output artifacts, and any messages for the human-in-the-loop gate.

This uniform signature means the workflow service can dispatch any agent without knowing what it does internally. It also means you can swap a mock agent for a live one by changing a single configuration flag.

## Why inheritance over composition

You might ask: why not use composition with dependency injection? The answer is pragmatism. Fifteen agents share 80% of their infrastructure — logging, error handling, database access, artifact storage. The base class handles that. The remaining 20% is the agent-specific logic that each subclass overrides.

Composition would mean repeating the 80% in every agent. Inheritance lets you write it once and override the 20%. When you need a sixteenth agent, you subclass `BaseAgent` and fill in `execute()`.

## The agent roster

### 1. Product Director

The Product Director is the strategic brain. It takes a raw niche idea and shapes it into a product definition: target audience, core promise, unique angle, and success criteria.

**Inputs:** Niche keyword, market category, author expertise level.
**Outputs:** Product brief (JSON), audience persona, competitive positioning statement.
**Failure mode:** Vague briefs that downstream agents can't act on. Mitigated by requiring structured output with mandatory fields.

### 2. Market Researcher

The Market Researcher gathers intelligence. It queries public data sources, analyses competitor pricing, identifies content gaps, and estimates search volume for target keywords.

**Inputs:** Product brief from the Director.
**Outputs:** Market report with competitor matrix, pricing benchmarks, demand signals.
**Failure mode:** Stale or hallucinated data. Mitigated by grounding queries in verifiable sources and caching results.

### 3. Opportunity Scorer

The Opportunity Scorer turns research into a number. It weights demand, competition, monetisation fit, and author alignment to produce a score from 0 to 100.

**Inputs:** Market report, product brief.
**Outputs:** Opportunity score with component breakdown, go/no-go recommendation.
**Failure mode:** False positives on saturated markets. Mitigated by configurable scoring weights per category.

### 4. Positioning Strategist

The Positioning Strategist crafts the unique selling proposition. It finds the angle that differentiates this ebook from every competitor in the niche.

**Inputs:** Product brief, market report, opportunity score.
**Outputs:** Positioning statement, subtitle options, key differentiators.
**Failure mode:** Generic positioning that could apply to any book. Mitigated by requiring specific competitor comparisons.

### 5. Outline Architect

The Outline Architect designs the book's structure. It creates a hierarchical chapter and section blueprint that balances depth with readability.

**Inputs:** Product brief, positioning statement, target page count.
**Outputs:** Complete outline with chapter titles, section breakdowns, word count targets.
**Failure mode:** Unbalanced chapters or missing logical flow. Mitigated by enforcing section count ranges and dependency ordering.

### 6. Manuscript Author

The Manuscript Author writes the actual prose. It takes the outline and generates chapter-by-chapter content, maintaining voice consistency across the entire manuscript.

**Inputs:** Outline, positioning statement, style guide.
**Outputs:** Complete manuscript in markdown, chapter by chapter.
**Failure mode:** Voice drift, repetition, factual errors. Mitigated by chapter-level context windows and editorial review loops.

### 7. Editorial Agent

The Editorial Agent reviews the manuscript for structure, flow, grammar, and style. It doesn't rewrite — it annotates with specific revision suggestions.

**Inputs:** Manuscript, style guide, outline.
**Outputs:** Editorial report with line-numbered suggestions, priority ratings.
**Failure mode:** Over-editing that strips the author's voice. Mitigated by configurable strictness levels.

### 8. Fact-Check & Compliance Agent

The Fact-Check Agent verifies claims, statistics, and legal compliance. It flags anything that could be defamatory, copyright-infringing, or factually wrong.

**Inputs:** Manuscript, niche category, jurisdiction (default: Australia).
**Outputs:** Fact-check report with verified/unverified flags, compliance warnings.
**Failure mode:** Missing niche-specific regulations. Mitigated by a compliance rulebook that can be updated per jurisdiction.

### 9. Cover Creative Director

The Cover Creative Director generates the cover concept. It produces image prompts for the front cover, spine, and back cover, along with typography recommendations.

**Inputs:** Product brief, positioning statement, target audience.
**Outputs:** Cover brief with image prompts, colour palette, font pairings.
**Failure mode:** Generic stock-photo aesthetics. Mitigated by requiring mood boards and style references.

### 10. Ebook Production Agent

The Ebook Production Agent assembles the final files. It converts the markdown manuscript into EPUB and PDF formats, embeds metadata, and validates against publishing standards.

**Inputs:** Final manuscript, cover assets, metadata (ISBN, publisher, author).
**Outputs:** EPUB file, PDF file, validation report.
**Failure mode:** Formatting errors in conversion. Mitigated by post-generation validation with industry tools.

### 11. Sales Copywriter

The Sales Copywriter produces all the marketing text: Amazon description, landing page copy, email sequences, and social media snippets.

**Inputs:** Product brief, positioning statement, target audience.
**Outputs:** Sales page copy, Amazon description, email sequence (5 emails), social posts.
**Failure mode:** Feature-focused copy instead of benefit-focused. Mitigated by requiring benefit-driven templates.

### 12. Funnel & Fulfilment Agent

The Funnel Agent designs the purchase and delivery flow. It configures Stripe products, sets up webhook handlers, and defines the download delivery mechanism.

**Inputs:** Product brief, pricing strategy, platform requirements.
**Outputs:** Funnel diagram, Stripe product config, webhook handler map.
**Failure mode:** Broken download links or expired tokens. Mitigated by tokenized URLs with configurable expiry.

### 13. Analytics & Optimisation Agent

The Analytics Agent tracks performance. It monitors sales, conversion rates, refund rates, and customer feedback to identify optimisation opportunities.

**Inputs:** Sales data, funnel metrics, customer feedback.
**Outputs:** Analytics dashboard data, A/B test suggestions, optimisation recommendations.
**Failure mode:** Vanity metrics that don't drive decisions. Mitigated by focusing on actionable KPIs.

### 14. Obsidian Knowledge Manager

The Knowledge Manager publishes research, drafts, and reference material to the Obsidian vault. It maintains the knowledge graph that connects ideas across projects.

**Inputs:** All artifacts from the current project, vault structure.
**Outputs:** Vault notes with backlinks, tags, and metadata.
**Failure mode:** Vault clutter from incomplete projects. Mitigated by only publishing on project completion.

### 15. Launch Strategist

The Launch Strategist plans the go-to-market. It creates a timeline, identifies launch platforms, coordinates email sequences, and defines success milestones.

**Inputs:** Product brief, sales copy, funnel config, analytics baseline.
**Outputs:** Launch plan with timeline, platform checklist, milestone definitions.
**Failure mode:** Launching before the product is ready. Mitigated by requiring all upstream artifacts before execution.

## Wiring agents to the workflow

Each agent is registered in the workflow service with its dependencies explicitly declared:

```python
agents = [
    ProductDirector(),
    MarketResearcher(),
    OpportunityScorer(),
    PositioningStrategist(),
    OutlineArchitect(),
    ManuscriptAuthor(),
    EditorialAgent(),
    FactCheckComplianceAgent(),
    CoverCreativeDirector(),
    EbookProductionAgent(),
    SalesCopywriter(),
    FulfilmentAgent(),
    AnalyticsOptimisationAgent(),
    ObsidianKnowledgeManager(),
    LaunchStrategist(),
]
```

The workflow service resolves the dependency graph and executes agents in topological order. If the Manuscript Author fails, the Editorial Agent and Fact-Check Agent are skipped automatically — there's nothing to review.

## Mock vs live execution

Every agent supports two modes:

- **Mock mode:** Returns realistic synthetic output. Used for development, testing, and demonstrations without API costs.
- **Live mode:** Calls external APIs (LLMs, search, Stripe) to produce real output.

The mode is controlled by a single environment variable per agent. This means you can develop the entire pipeline with mock agents, then flip individual agents to live as you're ready.

## Error handling strategy

Agents fail. The question is how gracefully. The workforce uses a three-tier approach:

1. **Retry:** Transient failures (network timeouts, rate limits) are retried with exponential backoff.
2. **Circuit breaker:** If an agent fails three times in a row, it's marked unhealthy and skipped for the rest of the pipeline run.
3. **Human gate:** Critical failures (fact-check violations, compliance flags) pause the pipeline and wait for human approval before continuing.

This means a single agent failure doesn't kill the entire pipeline. You get as far as you can, fix the failure, and resume from where you left off.

## Testing each agent

Every agent has unit tests that verify:

- Input validation rejects malformed context.
- Mock execution returns structurally valid output.
- Live execution (when enabled) produces expected artifact types.
- Rollback cleans up partial state on failure.

The test suite runs in under 30 seconds with all agents in mock mode. This is your safety net when modifying agent logic or adding new agents.

## Adding a new agent

To add a 16th agent:

1. Create `app/agents/my_new_agent.py` with a class inheriting `BaseAgent`.
2. Implement `execute()`, `validate_input()`, and `rollback()`.
3. Add the agent to the `agents` list in the workflow service.
4. Write tests in `test_agents.py`.
5. Run the full test suite to verify nothing broke.

The existing 15 agents serve as templates. Copy the structure, change the logic, and you're done. The workflow service automatically picks up the new agent and integrates it into the dependency graph.

## Key takeaways

- One base class, fifteen specialisations.
- Uniform signatures enable generic workflow orchestration.
- Mock mode for development, live mode for production.
- Three-tier error handling: retry, circuit breaker, human gate.
- Adding a new agent is a 5-step process with existing templates.
