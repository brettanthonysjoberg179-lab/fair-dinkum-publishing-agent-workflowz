## The orchestration problem

Fifteen agents are useless if they can't work together. The service layer is what transforms a collection of independent specialists into a coherent production pipeline. It answers three questions:

1. **Which agent runs next?**
2. **What context does it receive?**
3. **What happens when it fails?**

The `WorkflowService` class is the answer to all three.

```python
class WorkflowService:
    def __init__(self, session, agents: list[BaseAgent]):
        self.session = session
        self.agents = {a.name: a for a in agents}
        self.graph = self._build_dependency_graph()
    
    async def run_full_pipeline(self, project_id: str) -> PipelineResult:
        ...
    
    async def run_from(self, project_id: str, agent_name: str) -> PipelineResult:
        ...
```

## The dependency graph

Each agent declares what it needs from its predecessors. The service builds a directed acyclic graph from these declarations and executes in topological order.

```
ProductDirector → MarketResearcher → OpportunityScorer → PositioningStrategist
    → OutlineArchitect → ManuscriptAuthor → EditorialAgent → FactCheckComplianceAgent
    → CoverCreativeDirector → EbookProductionAgent → SalesCopywriter
    → FulfilmentAgent → AnalyticsOptimisationAgent → ObsidianKnowledgeManager
    → LaunchStrategist
```

If the Opportunity Scorer returns a "no-go" verdict, the pipeline stops. No point writing a book the market doesn't want.

## Context accumulation

Each agent receives the accumulated artifacts from all previous agents. The context object grows as the pipeline progresses:

```python
@dataclass
class AgentContext:
    project_id: str
    phase: str
    artifacts: dict[str, Any]  # keyed by agent name
    db_session: Session
    config: PipelineConfig
    human_approvals: list[ApprovalRecord]
```

Early agents see a lean context. Later agents see the full history. The Manuscript Author doesn't need the Opportunity Score, but the Launch Strategist needs everything.

## State management

Projects move through well-defined states:

```
SCOPED → RESEARCHED → SCORED → POSITIONED → OUTLINED → DRAFTED → EDITED
    → VERIFIED → PRODUCED → MARKETED → FULFILLED → ANALYSED → PUBLISHED → LAUNCHED
```

Each agent transition updates the project state in the database. If the pipeline crashes mid-execution, you can resume from the last completed state instead of starting over.

```python
async def run_from(self, project_id: str, agent_name: str) -> PipelineResult:
    current_state = await self._get_project_state(project_id)
    start_index = self._state_index(agent_name)
    
    for agent in self._agents_from(start_index):
        if await self._should_skip(project_id, agent):
            continue
        result = await self._execute_with_retry(agent, context)
        if result.status == "failed":
            await self._handle_failure(agent, result, context)
            break
        await self._advance_state(project_id, agent.name)
```

## Error handling in practice

The three-tier error handling from Chapter 7 plays out differently at the service level:

### Tier 1: Retry with backoff

```python
async def _execute_with_retry(self, agent, context, max_retries=3):
    for attempt in range(max_retries):
        try:
            return await agent.execute(context)
        except TransientError as e:
            wait = 2 ** attempt
            logger.warning(f"{agent.name} failed (attempt {attempt+1}), retrying in {wait}s")
            await asyncio.sleep(wait)
    return AgentResult(status="failed", error="max_retries_exceeded")
```

Network timeouts, rate limits, and temporary API outages trigger retries. The exponential backoff prevents thundering herd problems.

### Tier 2: Circuit breaker

If an agent fails three times consecutively, the circuit breaker opens. The agent is marked unhealthy and skipped for the rest of the pipeline run. The project state is set to `BLOCKED` with a reference to the failing agent.

```python
class CircuitBreaker:
    def __init__(self, threshold=3):
        self.failures: dict[str, int] = {}
        self.threshold = threshold
    
    def record_failure(self, agent_name: str):
        self.failures[agent_name] = self.failures.get(agent_name, 0) + 1
    
    def is_open(self, agent_name: str) -> bool:
        return self.failures.get(agent_name, 0) >= self.threshold
```

### Tier 3: Human-in-the-loop

Some failures aren't transient — they're fundamental. A fact-check violation, a compliance flag, or a positioning conflict requires human judgment. The pipeline pauses and creates an approval record:

```python
@dataclass
class ApprovalRecord:
    agent_name: str
    artifact_key: str
    issue: str
    options: list[str]
    status: str = "pending"  # pending, approved, rejected
    resolved_by: str | None = None
    resolved_at: datetime | None = None
```

The human reviews the issue, selects an option, and the pipeline resumes from where it left off.

## Parallel execution

Some agents have no dependencies on each other and can run concurrently. The service layer detects these opportunities:

```python
# Cover design and sales copy don't depend on each other
parallel_group = [CoverCreativeDirector(), SalesCopywriter()]
results = await asyncio.gather(
    *[self._execute_with_retry(a, context) for a in parallel_group],
    return_exceptions=True
)
```

The Cover Creative Director and Sales Copywriter can work simultaneously because neither needs the other's output. This cuts total pipeline time by 15-20%.

## Pipeline configuration

Not every project needs every agent. The `PipelineConfig` lets you customise:

```python
@dataclass
class PipelineConfig:
    skip_agents: list[str] = field(default_factory=list)
    mock_agents: list[str] = field(default_factory=list)
    human_gates: list[str] = field(default_factory=list)
    max_retries: int = 3
    parallel_groups: list[list[str]] = field(default_factory=list)
    timeout_per_agent: int = 300  # seconds
```

A quick market validation might skip straight from Product Director to Opportunity Scorer. A full production run uses all fifteen agents. Same codebase, different configuration.

These logs feed into the analytics agent and can be shipped to any structured logging platform. You always know exactly where a project stands.

## Resuming interrupted pipelines

If the server crashes mid-pipeline, recovery is automatic:

1. Query the database for projects in `IN_PROGRESS` or `BLOCKED` state.
2. Identify the last completed agent for each project.
3. Rebuild the context from accumulated artifacts.
4. Resume from the next agent in the sequence.

No work is lost. The database is the source of truth, and artifacts are persisted after each agent completes.

## Key takeaways

- The service layer transforms independent agents into a coherent pipeline.
- Dependency graph determines execution order; context accumulates as you go.
- Three-tier error handling: retry, circuit breaker, human gate.
- Parallel execution where dependencies allow.
- Configurable pipeline — run all fifteen agents or just the ones you need.
- Structured logging and state management enable automatic recovery.
