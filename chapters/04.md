## The .gitignore

Before you write any code, configure Git to ignore the files that should never be committed.

```bash
cat > .gitignore << 'EOF'
# Python
__pycache__/
*.pyc
*.egg-info/
.venv/
venv/

# Data and secrets
.env
*.db
data/
!data/.gitkeep

# IDE
.vscode/
.idea/
*.swp

# OS
.DS_Store
Thumbs.db

# Docker
docker-compose.override.yml

# Alembic
alembic/versions/*.pyc
EOF

touch data/.gitkeep
```

The `.env` and `*.db` rules prevent secrets and local databases from leaking into Git. The `data/.gitkeep` trick ensures Git tracks the empty `data/` folder even though it ignores everything inside it.

## pyproject.toml: project metadata and dependencies

`pyproject.toml` is the modern Python project manifest. It defines metadata, build system, and dependencies in one file.

Create it:

```bash
cat > pyproject.toml << 'EOF'
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "fair-dinkum-publishing-agent-workforce"
version = "0.1.0"
description = "MCP server orchestrating the end-to-end ebook production pipeline."
requires-python = ">=3.10"
dependencies = [
    "fastapi[all]>=0.100.0",
    "uvicorn[standard]>=0.20.0",
    "pydantic>=2.0.0",
    "sqlalchemy>=2.0.0",
    "alembic>=1.12.0",
    "stripe>=7.0.0",
    "python-dotenv>=1.0.0",
]

[tool.hatch.build.targets.wheel]
packages = ["app"]
EOF
```

Key points:
- `requires-python = ">=3.10"` ensures you have modern language features like `match` statements and `list[str]` syntax.
- `fastapi[all]` pulls in the server plus optional dependencies like `python-multipart` for form handling.
- `sqlalchemy>=2.0.0` gives you the modern 2.0 API with `select()` constructs and improved typing.
- `hatchling` is the build backend. It’s lightweight and handles package discovery automatically.

## The PEP 668 reality check

If you’re on a modern Linux distribution like Fedora, Debian 12+, or Ubuntu 23.10+, you’ve hit PEP 668 — the “externally managed environment” restriction. It prevents `pip install` from modifying system Python.

You have three options:

**Option A: Virtual environment (preferred)**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

**Option B: User install with --break-system-packages**
```bash
pip install --break-system-packages -e .
```

**Option C: uv (fastest)**
```bash
pip install --break-system-packages uv
uv pip install -e .
```

This book assumes Option B or C for simplicity. If you prefer venvs, the commands are the same after activation. The code doesn’t care where the packages live.

For the Fair Dinkum Publishing project specifically, we installed dependencies system-wide because it’s a single-user workstation environment. If you’re deploying to a server, use a venv or Docker.

## Docker: one-command startup

Create `Dockerfile`:

```bash
cat > Dockerfile << 'EOF'
FROM python:3.13-slim

# Install system dependencies
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Install Python dependencies
COPY pyproject.toml .
RUN pip install --no-cache-dir -e .

# Copy application code
COPY app/ ./app/
COPY tests/ ./tests/
COPY alembic.ini .
COPY alembic/ ./alembic/

# Create data directory
RUN mkdir -p data

EXPOSE 8000

CMD ["uvicorn", "app.api.server:app", "--host", "0.0.0.0", "--port", "8000"]
EOF
```

Create `docker-compose.yml`:

```bash
cat > docker-compose.yml << 'EOF'
version: "3.9"

services:
  app:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=sqlite:///./data/app.db
      - APP_ENV=development
    volumes:
      - ./data:/app/data
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: fairdinkum
      POSTGRES_PASSWORD: changeme
      POSTGRES_DB: fairdinkum
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    restart: unless-stopped

volumes:
  postgres_data:
EOF
```

The `app` service builds from the Dockerfile and mounts the local `data/` directory so your database persists between restarts. The `db` service is optional — use it when you outgrow SQLite.

To start everything:
```bash
docker compose up
```

To stop:
```bash
docker compose down
```

## run_server.py: the local entry point

Not everyone wants to use Docker. Create a simple entry point for `uvicorn`:

```bash
cat > run_server.py << 'EOF'
#!/usr/bin/env python3
"""Entry point for the Fair Dinkum Publishing Agent Workforce server."""
import uvicorn

if __name__ == "__main__":
    uvicorn.run(
        "app.api.server:app",
        host="0.0.0.0",
        port=8000,
        reload=True,
    )
EOF
```

Run it:
```bash
python3 run_server.py
```

Open `http://localhost:8000/docs` in your browser. You should see the FastAPI automatic documentation. If you do, the scaffold is working.

## First tests: prove the scaffold works

Create `tests/test_scaffold.py`:

```bash
cat > tests/test_scaffold.py << 'EOF'
"""Tests that verify the project scaffold is correctly structured."""
import os
import sys
import pytest

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))


def test_project_root_exists():
    """Verify we're running from the correct directory."""
    assert os.path.exists("app")
    assert os.path.exists("tests")
    assert os.path.exists("pyproject.toml")


def test_app_packages_exist():
    """Verify all app packages are present."""
    packages = ["agents", "api", "core", "models", "services"]
    for pkg in packages:
        assert os.path.exists(f"app/{pkg}"), f"Missing package: app/{pkg}"
        assert os.path.exists(f"app/{pkg}/__init__.py"), f"Missing __init__.py in app/{pkg}"


def test_tests_directory_has_files():
    """Verify tests directory is not empty."""
    test_files = os.listdir("tests")
    assert len(test_files) > 0, "tests/ directory is empty"
    assert "test_scaffold.py" in test_files


def test_data_directory_exists():
    """Verify data directory exists for SQLite."""
    assert os.path.exists("data"), "data/ directory missing"


def test_git_repository_initialised():
    """Verify Git repository exists."""
    assert os.path.exists(".git"), "Git repository not initialised"


def test_pyproject_toml_valid():
    """Verify pyproject.toml can be parsed."""
    import tomllib
    with open("pyproject.toml", "rb") as f:
        config = tomllib.load(f)
    assert "project" in config
    assert config["project"]["name"] == "fair-dinkum-publishing-agent-workforce"
EOF
```

Run the tests:

```bash
python3 -m pytest tests/test_scaffold.py -v
```

You should see all six tests pass. If they don’t, fix the scaffold before proceeding. The rest of the book assumes a working environment.

## Troubleshooting

**“pip install fails with externally managed environment”**
Use `pip install --break-system-packages -e .` or create a virtual environment with `python3 -m venv .venv && source .venv/bin/activate`.

**“Docker build fails because of network timeout”**
Docker needs to download the Python base image. If you’re on a slow connection, increase the timeout or use a local mirror.

**“Tests can’t find the app module”**
Make sure you’re running tests from the project root and that `sys.path.insert(0, ...)` is in every test file.

**“Git commit fails because user.email is not set”**
Run `git config user.email "you@example.com"` and `git config user.name "Your Name"`.
